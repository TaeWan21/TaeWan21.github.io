1. Problem Formulation

이 논문은 하나 이상의 LLM prompt를 가진 compound AI system을, 제한된 rollout 예산 안에서 downstream task에 적응시키는 것을 목표로 한다. 현재 널리 쓰이는 방법은 GRPO 같은 Reinforcement Learning with Verifiable Rewards(RLVR)로, task의 성공 지표를 rollout 끝의 scalar reward로 바꿔 policy gradient를 추정한다. 이 방식은 효과적이지만 새 task 하나에 수만 개의 rollout이 필요하고, 가장 큰 model이나 API 뒤의 model에는 weight를 건드릴 수 없어 적용이 막힌다. 대안인 prompt optimizer(MIPROv2 등)는 weight를 고정한 채 prompt만 바꾸므로 싸게 돌지만, global score 하나로 Bayesian search를 하거나 최고 후보만 greedy하게 다듬어 성능 상한이 낮았다. 저자들은 rollout이 남기는 것이 결국 자연어 trace(각 module의 instruction, reasoning, tool 호출, 그리고 reward로 압축되기 전 compiler error 같은 평가 과정)라는 점에 주목한다. 이 trace를 scalar로 눌러 버리는 대신 LLM이 자연어로 reflection해 prompt를 고치고, task instance별 Pareto frontier에서 다음 후보를 고르는 진화적 optimizer GEPA(Genetic-Pareto)를 제안한다.

논문은 compound AI system을 \(\Phi = (M, C, \mathcal{X}, \mathcal{Y})\)로 정식화한다. \(M = \langle M_1, \dots, M_{\lvert M \rvert} \rangle\)은 LLM module들, \(C\)는 제어 흐름, \(\mathcal{X}, \mathcal{Y}\)는 전체 입출력 schema이다. 각 module \(M_i = (\pi_i, \theta_i, \mathcal{X}_i, \mathcal{Y}_i)\)는 prompt \(\pi_i\)(instruction과 few-shot demonstration)와 weight \(\theta_i\)를 가진다.

  • 입력: system \(\Phi\)와 seed prompt, 학습 데이터 \(\mathcal{D}_{\text{train}} = \{(x, m)_i\}\)(입력 \(x\)와 gold answer, rubric, unit test 같은 평가 metadata \(m\)), metric \(\mu: \mathcal{Y} \times \mathcal{M} \to [0, 1]\), 텍스트 feedback까지 돌려주는 feedback function \(\mu_f\), rollout 예산 \(B\)
  • 출력: 모든 module의 prompt 집합 \(\Pi_\Phi = \langle \pi_1, \dots, \pi_{\lvert M \rvert} \rangle\). weight \(\Theta_\Phi\)는 고정한다.
  • 최종 목표: rollout 수가 \(B\)를 넘지 않는 조건에서 held-out 성능을 최대화한다.
\[\langle \Pi^\ast, \Theta^\ast \rangle_\Phi = \arg\max_{\langle \Pi, \Theta \rangle_\Phi} \mathbb{E}_{(x, m) \sim \mathcal{T}}\left[\mu\!\left(\Phi(x; \langle \Pi, \Theta \rangle_\Phi), m\right)\right], \quad \text{s.t. } \#\text{rollouts} \le B\]

문제를 prompt와 weight 양쪽에 대해 정의한 이유는, prompt 공간에서 움직이는 GEPA와 weight 공간에서 움직이는 GRPO를 같은 rollout 예산 위에서 비교하기 위해서이다.

2. Limitations of Existing Works

[Scalar Reward Collapse] GRPO는 rollout 하나가 만든 reasoning chain, tool 출력, 평가 과정의 error message를 모두 버리고 성공 여부 하나만 policy gradient의 신호로 쓴다. 정보 대부분이 학습에 쓰이지 못하므로 새 task를 익히는 데 수만에서 수십만 rollout이 든다. 비싼 tool 호출이 섞인 시스템이나 sampling 예산이 제한된 환경에서는 이 비용이 병목이 되고, 가장 성능 좋은 model의 weight는 애초에 접근할 수 없는 경우가 많다.

[Greedy Prompt Search] TextGrad나 APO 같은 텍스트 feedback 기반 prompt optimizer는 매 iteration 최고 점수 후보(또는 상위 N개 beam)에서만 다음 후보를 만든다. 하나의 지배적 전략이 발견되면 그것을 넘어서기 어렵고, optimizer는 같은 후보를 다듬는 데 예산을 소진한다. Figure 6(a)가 그 예로, 첫 자식 노드 이후 18개 후보가 모두 같은 부모에서 나와 더 나아지지 못한다.

[Global Reward and Few-shot Bloat] MIPROv2는 instruction과 few-shot demonstration을 Bayesian optimization으로 함께 고르지만, 후보를 평가하는 신호가 전체 task의 평균 점수 하나이다. 어느 module의 어떤 지시가 실패를 만들었는지는 알 수 없다. 또한 demonstration 여러 개를 동시에 넣기 때문에 prompt가 길어지고, 복잡한 task에서는 demonstration 하나만으로도 context가 크게 늘어 추론 비용이 커진다.

3. Methodology

[Figure 3] GEPA의 한 iteration이다. 후보 pool \(\mathcal{P}\)의 각 후보는 task별 점수 행렬을 가진다. Pareto-based filtering이 task마다 최고 점수인 후보만 남기고, 그중 하나를 sampling해 Reflective Prompt Mutation을 적용하거나 둘을 골라 System Aware Merge를 적용한다. 새 후보 \(P_{\text{new}}\)는 minibatch에서 먼저 평가되고, 개선되었을 때만 전체 \(\mathcal{D}_{\text{pareto}}\)에서 평가되어 pool에 들어간다.

GEPA의 pipeline은 다음과 같다.

  • ① Pareto frontier에서 진화시킬 후보 \(\Phi_k\)를 sampling한다(3.3절).
  • ② 갱신할 module \(j\)를 round-robin으로 고르고, \(\mathcal{D}_{\text{feedback}}\)에서 minibatch를 뽑아 \(\Phi_k\)를 실행하며 trace와 \(\mu_f\)의 feedback을 모은다.
  • ③ reflection LM이 (현재 prompt, trajectory, 점수, feedback)을 보고 module \(j\)의 새 prompt \(\pi_j'\)를 제안한다(3.2절).
  • ④ 새 후보를 같은 minibatch에서 평가해 점수가 오르면 pool에 넣고 부모를 기록한 뒤 \(\mathcal{D}_{\text{pareto}}\) 전체에서 평가한다.
  • ⑤ 예산이 다하면 \(\mathcal{D}_{\text{pareto}}\) 평균 점수가 가장 높은 후보를 반환한다.

3.1. Genetic Optimization Loop

GEPA는 \(\mathcal{D}_{\text{train}}\)을 두 부분으로 나눈다. \(\mathcal{D}_{\text{feedback}}\)은 minibatch rollout과 reflection에 쓰이고, \(\mathcal{D}_{\text{pareto}}\)(\(n_{\text{pareto}}\)개)는 후보 선택을 위한 점수표를 만드는 데 쓰인다. pool은 seed system 하나로 시작하며, 각 후보는 \(\langle \Pi, \Theta_{\text{frozen}} \rangle_\Phi\)의 구체적 instance이다. 새 후보는 기존 후보의 mutation이나 crossover로만 만들어지므로 부모의 학습 신호를 물려받고, ancestry가 기록되어 genetic tree가 쌓인다. 후보가 pool에 들어가는 조건은 부모보다 minibatch 점수가 높을 것 하나뿐이다. 즉 GEPA는 후보를 tree로 쌓아 가되, 어느 가지를 키울지는 3.3절의 Pareto 규칙이 정하는 진화 알고리즘이다.

3.2. Reflective Prompt Mutation: Trace에서 규칙을 뽑아내기

compound AI system이 실행되면 각 module의 입력, 출력, reasoning이 자연어 trace로 남는다. 이 trace를 최종 결과(성공/실패)와 함께 LLM에 보이면, LLM은 어느 module의 어떤 결정이 결과에 책임이 있는지를 implicit하게 credit assignment할 수 있다. GEPA는 이 능력을 module 단위 prompt 갱신에 쓴다.

저자들은 진단 신호를 두 종류로 구분한다. execution trace는 LLM이 생산한 텍스트이고, evaluation trace는 환경이 reward를 계산하는 과정에서 만드는 텍스트이다. code 평가라면 compile, 실행, profiling의 출력이 reward 0으로 눌리기 전에 존재한다. GEPA는 metric \(\mu\)를 feedback function \(\mu_f\)로 확장해, scalar 점수와 함께 이런 evaluation trace를 feedback_text로 돌려받는다. multi-hop system에서는 hop마다 아직 찾지 못한 문서를 알려 주는 식으로 module별 feedback도 가능하고, 사람이 쓴 채점 근거가 있으면 그것도 같은 자리에 넣을 수 있다.

mutation 절차는 다음과 같다. 선택된 후보를 minibatch에서 실행해 trace를 얻고, module \(j\)의 (현재 prompt \(\pi_j\), trajectory, 점수, feedback)을 reflection LM에 보여 성공과 실패의 원인을 prompt 요소에 귀속시키고 수정된 instruction을 제안하게 한다.

\[\pi_j' = \mathrm{UpdatePrompt}\!\left(\pi_j,\; \text{feedbacks},\; \text{traces}[j]\right)\]

[Figure 5] PUPA(privacy-preserving delegation) task에서 GEPA가 밟은 진화 경로의 일부이다. 괄호는 \(\mathcal{D}_{\text{pareto}}\) 점수이다. seed prompt(후보 0, 82.26)는 한 문장이다. 후보 2(90.99)는 PII 식별과 일반화 지침을 더하고, 후보 4(94.44)는 출력을 Reasoning과 Request로 나누며 이름과 code 사용을 금지한다. 후보 5(94.67)는 위치, 이름, 직업 상황, 가상 인물 처리 규칙을 근거와 함께 적고, 후보 11(97.6)은 부분 redaction을 금지하는 단계별 protocol로 마무리한다. 한 번의 reflection이 8점 이상을 올리기도 한다.

Figure 2의 HotpotQA 예처럼 GEPA가 만든 prompt는 few-shot 예시의 나열 대신 “first-hop 문서는 보통 하나의 entity만 다루므로 summary에 언급된 더 넓은 entity를 겨냥하라” 같은 선언적 규칙으로 채워진다. 핵심은 rollout 하나에서 점수 하나에 그치지 않고 “왜 실패했는가”에 대한 설명까지 얻으며, 이것이 prompt의 규칙으로 축적된다는 점이다.

3.3. Pareto-based Candidate Selection: 어느 후보를 진화시킬 것인가

다음 iteration에서 어느 후보를 mutation할지는 exploration과 exploitation의 균형을 정한다. 최고 점수 후보만 고르면 local optimum에 갇힌다. GEPA는 quality-diversity 계열의 “illumination” 전략을 쓴다. Algorithm 2를 옮기면 다음과 같다.

\[s^\ast[i] = \max_k S_{\mathcal{P}[k]}[i], \qquad \mathcal{P}^\ast[i] = \{\mathcal{P}[k] : S_{\mathcal{P}[k]}[i] = s^\ast[i]\}\]
  • \(S_{\mathcal{P}[k]}[i]\): 후보 \(k\)의 \(\mathcal{D}_{\text{pareto}}\) instance \(i\)에 대한 점수
  • \(s^\ast[i]\): instance \(i\)에서 지금까지의 최고 점수
  • \(\mathcal{P}^\ast[i]\): instance \(i\)에서 최고 점수를 낸 후보들

모든 \(\mathcal{P}^\ast[i]\)의 합집합이 후보 집합 \(\mathcal{C}\)이다. 즉 task instance 하나에서라도 1등인 후보는 살아남고, 모든 instance에서 다른 후보에게 지는(dominated) 후보는 제거된다. 남은 후보마다 자신이 1등인 instance의 수 \(f[\Phi]\)를 세고, 이에 비례한 확률로 하나를 sampling한다.

\[\Pr(\Phi_k) \propto f[\Phi_k] = \left\lvert \{\, i : \Phi_k \in \hat{\mathcal{P}}^\ast[i] \,\} \right\rvert\]

전체 평균은 낮아도 특정 유형의 문제를 유일하게 푸는 후보가 있으면 그 전략은 보존되고, 여러 instance를 이끄는 후보일수록 더 자주 확장된다. 따라서 Pareto 선택은 평균 점수라는 하나의 축을 instance 수만큼의 축으로 펼쳐, 서로 다른 “이기는 전략”들을 동시에 유지하는 규칙이다.

3.4. System Aware Merge: 계보 사이의 Crossover

mutation만으로는 서로 다른 가지에서 배운 교훈이 합쳐지지 않는다. GEPA+Merge는 두 후보를 골라 module 단위로 crossover한다. 조건은 엄격하다. 두 후보가 공통 조상을 가지되 서로 다른(disjoint) module 집합을 최적화했고, 둘 다 Pareto-optimal이며, 둘 다 조상보다 평균 점수가 높아야 한다. 이 조건이 맞으면 module마다 두 계보 중 그 module을 진화시킨 쪽의 prompt를 가져와 하나의 후보를 만든다. 예를 들어 한 계보가 query 생성 module을, 다른 계보가 답변 module을 개선했다면 각각의 개선판을 합친다. 조건이 엄격하므로 merge는 드물게 일어난다. 결과적으로 merge는 module별로 독립적으로 발견된 개선을 system 수준에서 합치는 연산이며, 그 효과는 model에 따라 갈린다(4.3절).

4. Experiments

4.1. Setup

benchmark는 여섯 개이다. HotpotQA(multi-hop QA), IFBench(instruction following), HoVer(retrieval 기반 claim 검증), PUPA(privacy-aware delegation), AIME-2025와 LiveBench-Math(수학)이며, 각각 기존 compound AI system과 feedback function이 붙어 있다. model은 Qwen3 8B와 GPT-4.1 Mini이다. 비교 대상은 GRPO(24,000 rollout, LoRA), MIPROv2(instruction과 few-shot 공동 최적화 및 instruction만), TextGrad, Trace(OptoPrime)이다. train/validation/test를 나누고, optimizer는 train의 내용에만 접근하며 validation은 점수만 볼 수 있다.

[Table 3] Pareto 선택은 greedy와 beam search보다 aggregate로 각각 6.4점, 7.3점 높다. HoVer에서는 beam search 41.00 대비 52.33으로 11.3점 차이이다. greedy는 IFBench에서 baseline 36.90보다 낮은 30.44로 떨어지는데, 한 후보를 반복해 다듬다가 과적합한 결과이다. 3.3절의 주장, 즉 instance별 1등을 모두 살려 두는 것이 같은 예산에서 더 좋은 해에 닿게 한다는 것을 뒷받침한다.

Merge. GEPA+Merge는 GPT-4.1 Mini에서 GEPA보다 최대 5점, aggregate로 1.1점을 더 얻지만, Qwen3 8B에서는 네 task 중 셋에서 오히려 낮다(IFBench 38.61 → 28.23). 저자들은 두 model에 같은 hyperparameter를 써서 mutation과 crossover 사이의 예산 배분과 merge 호출 시점이 Qwen3 8B에 맞지 않았다고 보며, 충분히 다른 계보가 생긴 뒤에 merge를 호출하는 adaptive 규칙을 future work로 남긴다.

Prompt 길이. 성능이 높은 optimizer일수록 prompt가 짧은 경향이 있고, GEPA의 prompt는 MIPROv2보다 최대 9.2배 짧다. few-shot demonstration을 나열하는 대신 규칙을 적기 때문이며, 입력 token 과금과 latency에 직접 영향을 준다. Wan et al.(2024)이 제안한 generalization gap(validation과 test 점수 차이) 분석에서도 reflection으로 진화한 instruction이 더 작은 gap을 보인다.

Inference-time search와 adversarial search. 풀어야 할 task 집합을 \(\mathcal{D}_{\text{train}}\)과 \(\mathcal{D}_{\text{pareto}}\)에 모두 넣으면 GEPA는 그 집합에 “과적합”하는 탐색기가 된다. AMD NPU kernel 생성(NPUEval)에서 GPT-4o의 10회 순차 refinement agent는 평균 vector utilization 4.25%, RAG를 붙이면 16.33%, MIPROv2를 더하면 19.03%인데, GEPA는 RAG 없이 30.52%에 도달하고 일부 kernel은 70%를 넘는다. KernelBench 35개 task에서는 fast1 점수가 0% 근처에서 20% 이상으로 오른다. reward 부호를 뒤집으면 adversarial prompt 탐색도 된다. AIME 2022~2024로 진화시킨 범용 distractor instruction(꿀은 상하지 않는다는 trivia와 엄격한 형식 지시의 조합)은 GPT-5 Mini의 AIME-2025 pass@1을 76%에서 10%로 떨어뜨렸다. 저자들은 이 결과들을 예비 실험으로 명시한다.

5. Conclusion

Contribution

  • [Reflective Prompt Evolution] rollout의 execution trace와 evaluation trace를 scalar로 누르지 않고 LLM reflection의 입력으로 써서 module별 prompt를 갱신하는 optimizer를 제안한다. Qwen3 8B에서 GRPO(24k rollout) 대비 여섯 task 평균 +6점, 최대 +19점을 최대 35배 적은 rollout으로 얻는다.
  • [Pareto-based Selection] task instance별 최고 후보를 모두 보존하고 이끄는 instance 수에 비례해 sampling하는 선택 규칙으로, greedy와 beam search 대비 aggregate +6.4, +7.3점을 더 얻는다.
  • [Generalization] instruction만 최적화해도 few-shot 공동 최적화(MIPROv2)를 모든 설정에서 넘고(GPT-4.1 Mini +13.33 vs +5.64), prompt가 최대 9.2배 짧으며, 약한 model로 최적화한 prompt가 다른 계열의 강한 model로 옮겨 간다(+9.00).

Limitations

  • [Validation-dominated Budget] rollout 예산의 대부분이 \(\mathcal{D}_{\text{pareto}}\) 평가에 쓰인다. 학습 신호를 만드는 train rollout은 79~737개에 그친다. 저자들은 더 작은 validation set이나 동적으로 고른 부분집합으로 점수를 추적하는 방향을 제시한다.
  • [Merge Scheduling] crossover의 이득은 model에 따라 갈리고, mutation과 crossover 사이의 예산 배분과 호출 시점이 고정 hyperparameter이다. 이 한계가 Qwen3 8B에서 GEPA+Merge의 성능 하락으로 나타난다.
  • [AIME Exception] Qwen3 8B의 AIME-2025에서는 GRPO(38.00)가 GEPA(32.00)를 앞선다. 수학 추론처럼 prompt 규칙보다 weight 갱신이 유효한 영역이 있음을 시사하지만, 논문은 원인을 분석하지 않는다.
  • [Preliminary Extensions] kernel 생성과 adversarial search는 GPT-4o와 GPT-5 Mini로 한 초기 실험이며, 저자들도 체계적 후속 연구가 필요하다고 명시한다.

6. Optimizer는 무엇에서 배우는가

GRPO (weight-space RL)

\[\nabla_\theta \, \mathbb{E}\left[\hat{A}_i \log \pi_\theta(y_i \mid x)\right], \qquad \hat{A}_i = \frac{r_i - \mu_r}{\sigma_r}\]
  • “이 rollout이 group 평균보다 나았는가?”에서 배운다.
  • 하지만 \(r_i\) 하나로 trace 전체를 대표하므로 정보 대부분이 버려지고, 수만 rollout과 weight 접근이 필요하다.

MIPROv2 (Bayesian instruction + demo search)

\[\Pi^\ast = \arg\max_{\Pi \in \text{proposals}} \bar{\mu}(\Pi), \quad \text{via surrogate over (instruction, demos)}\]
  • “어떤 instruction과 demonstration 조합이 평균 점수를 올리는가?”에서 배운다.
  • 하지만 신호가 global 평균 하나라 module별 원인을 알 수 없고, demonstration 때문에 prompt가 길어진다.

TextGrad / APO (textual gradient, greedy)

\[\pi' = \mathrm{LLM}_{\text{edit}}(\pi, \text{critique}), \qquad \pi \leftarrow \arg\max_{\text{best or top-}N}\]
  • “이 prompt의 어디가 문제인가?”를 자연어로 배운다.
  • 하지만 최고 후보에서만 확장하므로 첫 좋은 전략에 갇힌다(Table 3의 +6.05, +5.11).

GEPA

\[\pi_j' = \mathrm{UpdatePrompt}(\pi_j, \mu_f\text{-feedback}, \text{traces}[j]), \qquad \Pr(\Phi_k) \propto \left\lvert \{ i : \Phi_k \text{ is best on } i \} \right\rvert\]
  • “어느 module의 어떤 지시가 어떤 instance에서 왜 실패했는가?”를 배우고, instance별로 이기는 전략을 모두 살려 둔다.
  • 하지만 예산의 대부분을 후보 평가에 쓰고, 수학처럼 weight 갱신이 더 유효한 영역이 남아 있다.

따라서 이 논문의 핵심은 단순히 “RL 대신 prompt를 튜닝했다”가 아니다. reward로 압축되기 전의 자연어 trace를 학습 신호로 되살리고, 그 신호로 module 단위 prompt를 진화시키며, 후보의 생존을 instance별 Pareto frontier로 정하는 세 요소를 하나의 진화 loop 안에 묶어, 적은 rollout에서도 RL을 넘는 sample efficiency를 만든 구조이다.
